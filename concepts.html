NLP Concepts

The building blocks behind the pipeline, grouped into four stages — text preprocessing, feature engineering, language representation, and language models.

Stage 1

Text Preprocessing

Sentence Segmentation
Definition
Dividing a block of text into individual sentences.
Purpose
Many downstream steps — tokenization, embeddings — operate per sentence, so splitting text at sentence boundaries keeps each processing unit meaningful.
How it works
Rule-based or model-based boundary detection using punctuation, abbreviation lists, and capitalization cues for English, or sentence-ending punctuation for Gujarati.
Example
In our bilingual English–Gujarati QA system, a long Gujarati paragraph answer is segmented into sentences before being scored for relevance to the question.
Advantages
Keeps context units coherent; simplifies later processing.
Limitations
Abbreviations and non-standard punctuation can cause false splits, especially across scripts.
Applications
Summarization, sentence-level retrieval, translation.
Tokenization
Definition
Splitting raw text into smaller units — words, subwords, or characters — that a model can process.
Purpose
Neural networks operate on numbers, not text; tokenization is the first translation step.
How it works
A tokenizer applies rules or a learned vocabulary (e.g. Byte-Pair Encoding) to break text into tokens, then maps each token to an ID.
Example
In our bilingual English–Gujarati QA system, tokenization separates English words and Gujarati script into individual tokens before feature extraction.
Advantages
Handles rare and compound words gracefully via subwords.
Limitations
Script-specific quirks (like Gujarati conjuncts) need tokenizers trained on that script, not borrowed from English.
Applications
Every step downstream: feature extraction, embeddings, search.
Case Normalization
Definition
Standardizing letter casing (uppercase/lowercase) across text.
Purpose
Prevents the same word in different cases from being treated as different tokens.
How it works
Lowercasing applies to English text; Gujarati has no case distinction, so this step is skipped entirely on the Gujarati path.
Example
In our system, "Gandhinagar" and "gandhinagar" are normalized to the same token before English feature extraction, while Gujarati text bypasses this step.
Advantages
Reduces vocabulary size, improves matching consistency.
Limitations
Can lose meaningful distinctions, such as proper nouns or acronyms, if applied carelessly.
Applications
Search, TF-IDF, keyword matching.
Stop-word Removal
Definition
Removing common, low-information words (like "the", "is", "and") before further processing.
Purpose
Focuses downstream steps on words that carry more meaning, and shrinks the vocabulary.
How it works
Words are checked against a language-specific stop-word list and dropped.
Example
Our bilingual system uses a separate English and Gujarati stop-word list, so common function words are filtered from each language's path independently.
Advantages
Reduces noise and computation for frequency-based methods like TF-IDF.
Limitations
Can remove words that matter for question phrasing (e.g. negations like "not").
Applications
TF-IDF, search indexing, classification.
Stemming
Definition
Cutting a word down to an approximate root form using fixed rules.
Purpose
Groups related word forms together without needing a dictionary.
How it works
Rule-based suffix stripping (e.g. removing "-ing", "-ed", or Gujarati inflectional endings).
Example
The Gujarati path in our pipeline uses stemming, since lightweight rule-based stripping is easier to build for Gujarati morphology than a full lemmatizer.
Advantages
Fast, simple, no dictionary required.
Limitations
Can produce non-words or over-strip roots.
Applications
Search indexing, quick text normalization.
Lemmatization
Definition
Reducing a word to its dictionary base form (lemma) using vocabulary and grammar rules.
Purpose
Produces linguistically correct base forms, which is more accurate than stemming.
How it works
Uses a lexicon and part-of-speech tagging to look up the correct base form of a word.
Example
The English path in our pipeline uses lemmatization ("running" → "run"), since mature English lemmatizers are readily available.
Advantages
More accurate normalization than stemming; always produces real words.
Limitations
Slower, and needs language-specific resources that may not exist for Gujarati.
Applications
QA, translation, tasks needing grammatical accuracy.
Noise Removal
Definition
Stripping out non-content elements from text, such as HTML tags, special characters, and boilerplate formatting.
Purpose
Prevents irrelevant symbols from being treated as meaningful tokens.
How it works
Pattern-based rules (e.g. regular expressions) strip out markup and unwanted characters.
Example
PDF documents used as sources in our QA system often carry leftover formatting artifacts that are stripped before tokenization.
Advantages
Cleans the text before more expensive processing steps.
Limitations
Overly aggressive rules can strip meaningful punctuation or characters.
Applications
Web-scraped and PDF-extracted text, social media data.
Text Cleaning
Definition
The broader process of removing URLs, extra whitespace, encoding errors, and other artifacts before analysis.
Purpose
Ensures text entering the pipeline is well-formed and consistent.
How it works
Combines noise removal with whitespace normalization and encoding fixes.
Example
URLs and stray whitespace in scraped Gujarati source text are cleaned before the text is Unicode-normalized and tokenized.
Advantages
Improves the reliability of every step downstream.
Limitations
Needs to be tuned per data source; overcleaning can destroy meaningful content.
Applications
Data preprocessing for any NLP pipeline.
Stage 2

Feature Engineering

Bag of Words
Definition
A representation of text as an unordered set of word counts, ignoring grammar and word order.
Purpose
Turns text into a numeric form that simple models can work with.
How it works
Build a vocabulary from the corpus, then represent each document as a vector of word counts.
Example
A short Gujarati answer candidate can be represented as counts of its vocabulary terms before being scored against the question.
Advantages
Simple, fast, easy to interpret.
Limitations
Ignores word order and context entirely.
Applications
Basic classification, spam filtering.
N-Grams
Definition
Contiguous sequences of N words (or characters) used as features instead of single words.
Purpose
Captures some local word order and context that Bag of Words misses.
How it works
A sliding window of size N moves across tokenized text, generating overlapping sequences.
Example
A bigram like "government scheme" carries more signal for a Government Services query than "government" and "scheme" scored separately.
Advantages
Captures short phrases and local word order.
Limitations
Vocabulary size grows quickly as N increases.
Applications
Language modeling, text classification, autocomplete.
TF (Term Frequency)
Definition
A count of how often a word appears in a document, usually normalized by document length.
Purpose
Highlights words that occur frequently within a specific document.
How it works
Count occurrences of a term and divide by the total number of terms in the document.
Example
A high term frequency for "Gandhinagar" in a passage signals that the passage is about Gandhinagar.
Advantages
Very fast, trivial to compute.
Limitations
Common words dominate; no notion of importance across documents.
Applications
Basic word-frequency analysis.
IDF (Inverse Document Frequency)
Definition
A measure of how rare or common a word is across an entire document collection.
Purpose
Down-weights words that appear in nearly every document and are therefore uninformative.
How it works
Computed as the logarithm of total documents divided by the number of documents containing the term.
Example
A word appearing in almost every document in our QA knowledge base gets a low IDF weight.
Advantages
Surfaces distinctive, document-specific terms.
Limitations
Needs the full corpus to compute; doesn't account for meaning.
Applications
Search ranking, keyword extraction.
TF-IDF
Definition
The product of TF and IDF, scoring a word by how important it is to one document relative to the whole collection.
Purpose
Balances local frequency against corpus-wide rarity to find genuinely distinctive terms.
How it works
Multiply a term's frequency in a document by its inverse document frequency across the corpus.
Example
TF-IDF vectors are used as one retrieval method for surfacing candidate passages before our QA system embeds and re-ranks them.
Advantages
Fast, interpretable, no GPU needed.
Limitations
Blind to meaning — exact words must match.
Applications
Lightweight keyword search, document ranking.
Stage 3

Language Representation

One-Hot Encoding
Definition
Representing each word as a vector with a single 1 in the position for that word and 0s everywhere else.
Purpose
Gives every distinct word a unique, unambiguous numeric identity.
How it works
A vocabulary is built and indexed; each word's vector has exactly one active position.
Example
An early proof-of-concept version of our pipeline used one-hot vectors before switching to embeddings for semantic search.
Advantages
Simple, unambiguous, no training required.
Limitations
Vectors are huge and sparse, and carry no notion of similarity between words.
Applications
Baseline models, simple classification tasks.
Word Embeddings
Definition
Dense numerical vectors that represent the meaning of a word, sentence, or document in a continuous space.
Purpose
Let a computer compare meaning, not just matching characters — "doctor" and "physician" land near each other.
How it works
A trained encoder model maps text to a fixed-length vector; semantic similarity becomes distance in that vector space.
Example
In our bilingual system, a 384-dimension vector represents the sentence "The capital of Gujarat is Gandhinagar" for semantic search.
Advantages
Enables semantic (meaning-based) search rather than exact keyword matching.
Limitations
Quality depends entirely on training data; multilingual embeddings need multilingual training corpora.
Applications
Semantic search, clustering, recommendation, retrieval for QA.
Word2Vec
Definition
An algorithm that learns one dense vector per whole word by predicting nearby words in a large corpus.
Purpose
Captures word meaning from usage patterns without manual labeling.
How it works
A shallow neural network is trained to either predict a word from its context (CBOW) or context from a word (Skip-gram).
Example
Word2Vec-style vectors can group related terms in an English question, like "doctor" and "physician", close together in vector space.
Advantages
Fast to train, well understood, captures useful word relationships.
Limitations
Cannot represent out-of-vocabulary words; one fixed vector per word ignores multiple meanings.
Applications
General word-similarity tasks, feature input for classifiers.
FastText
Definition
An extension of Word2Vec that learns vectors from character n-grams and sums them to build a word's vector.
Purpose
Handles rare, misspelled, and morphologically complex words far better than whole-word models.
How it works
Each word is broken into overlapping character n-grams; the word's embedding is the sum of its n-gram vectors.
Example
FastText's subword approach is well suited to our Gujarati path, where a single root can take many inflected forms.
Advantages
Handles rare and misspelled words gracefully; works well for morphologically rich languages like Gujarati.
Limitations
Slightly larger memory footprint than Word2Vec.
Applications
Morphologically rich languages, spelling-tolerant search.
Contextual Embeddings
Definition
Word representations that change depending on the surrounding sentence, rather than one fixed vector per word.
Purpose
Captures the fact that a word's meaning shifts with context, something static embeddings can't do.
How it works
A model reads the full sentence and produces a vector for each word conditioned on everything around it.
Example
Models such as BERT and mBERT generate contextual embeddings that help understand the meaning of words based on their surrounding context — the multilingual variant, mBERT, is what makes the Gujarati path possible.
Advantages
Resolves ambiguity that static embeddings can't (e.g. "bank" of a river vs. a bank).
Limitations
Computationally heavier than static embeddings; needs a trained model to run.
Applications
Extractive QA, semantic search, classification.
Stage 4

Language Models

Statistical Language Models
Definition
Models that estimate the probability of a word sequence using frequency counts from a training corpus.
Purpose
Provide a simple, interpretable way to predict what word is likely to come next.
How it works
N-gram frequency counts are used to estimate the probability of a word given the previous N-1 words.
Example
An n-gram language model can flag that "the capital of Gujarat is ___" is far more likely to be followed by "Gandhinagar" than an unrelated word.
Advantages
Simple, fast, requires no neural network training.
Limitations
Struggles with long-range context and unseen word combinations.
Applications
Early spell-checkers, basic autocomplete.
Neural Language Models
Definition
Models that use neural networks to predict word probabilities based on learned, dense representations of context.
Purpose
Capture longer-range dependencies and generalize better to unseen phrasing than statistical models.
How it works
A neural network (recurrent or transformer-based) is trained to predict the next word given prior context, learning patterns rather than memorizing counts.
Example
Machine translation between English and Gujarati in our project relies on a neural language model to generate fluent target-language text.
Advantages
Handles longer context and generalizes to phrasing not seen during training.
Limitations
Needs much more data and compute than statistical models.
Applications
Machine translation, text generation, autocomplete.
Transformer-based Representations
Definition
A neural network architecture built on self-attention, which lets every word in a sequence weigh every other word.
Purpose
Captures long-range context far better than earlier recurrent architectures, and trains in parallel.
How it works
Stacks of attention and feed-forward layers process an entire sequence at once, learning which words matter to which.
Example
BERT, mBERT, GPT, and Llama are all transformer variants — our system's mBERT-based embeddings and answer generation both depend on this architecture.
Advantages
State-of-the-art accuracy across nearly all NLP tasks.
Limitations
Computationally heavy; needs large data and compute to train from scratch.
Applications
Translation, summarization, question answering, code generation.
