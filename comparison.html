Comparative Analysis

Five head-to-head comparisons that shaped the design decisions in this pipeline.

Comparison

Retrieval QA vs. Generative QA

Aspect Retrieval QA Generative QA
Working Extracts an exact span from source text Generates a new sentence conditioned on retrieved context
Complexity Lower — no generation model needed Higher — needs a language model plus retrieval
Advantages Grounded, fast, hard to hallucinate Fluent, can synthesize across multiple passages
Disadvantages Answer must exist verbatim in source Can hallucinate if retrieval is weak
Use cases FAQ lookup, form-field extraction Conversational assistants, document chatbots
Comparison

BERT vs. mBERT

Aspect BERT mBERT
Working Contextual encoder trained on English text Same architecture trained jointly on 100+ languages
Complexity Single-language vocabulary Shared multilingual vocabulary, larger training set
Advantages Best-in-class for English tasks One model covers many languages, including Gujarati
Disadvantages No support for non-English scripts Slightly lower per-language accuracy than a dedicated model
Use cases English extractive QA, classification Cross-lingual and bilingual QA
Comparison

Word2Vec vs. FastText

Aspect Word2Vec FastText
Working Learns one vector per whole word Learns vectors from character n-grams, then sums per word
Complexity Simpler, smaller model Slightly heavier due to subword vectors
Advantages Fast to train, well understood Handles rare and misspelled words gracefully
Disadvantages Cannot represent out-of-vocabulary words Slightly larger memory footprint
Use cases General word-similarity tasks Morphologically rich languages like Gujarati
Comparison

Stemming vs. Lemmatization

Aspect Stemming Lemmatization
Working Chops word endings using fixed rules Maps a word to its dictionary base form using vocabulary and grammar
Complexity Lower — rule-based, no linguistic knowledge needed Higher — needs POS tagging and a lexicon
Advantages Fast, lightweight, no external resources Produces real words, more accurate normalization
Disadvantages Can produce non-words or over-strip roots Slower, requires language-specific resources
Use cases Quick indexing, search engines QA, translation, tasks needing grammatical accuracy
Comparison

TF vs. TF-IDF

Aspect TF TF-IDF
Working Counts raw frequency of a word in a document Scales frequency by how rare the word is across all documents
Complexity Simplest — single-document statistic Slightly higher — requires corpus-wide document frequencies
Advantages Very fast, trivial to compute Down-weights common words, highlights distinctive terms
Disadvantages Common words dominate, no notion of importance Still blind to meaning — exact words must match
Use cases Basic word-frequency analysis Keyword-based document ranking, lightweight search
